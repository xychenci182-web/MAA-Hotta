# MAA Hotta

在 Android 上自动跑《幻塔》日常。运行方式对齐 [MAA-Meow](https://github.com/Aliothmoon/MAA-Meow)：无障碍/Shizuku 截图与点击、悬浮控制、任务链。不包含明日方舟或 MAA Core。

## 能做什么

按账号循环执行：

1. 登录 / 切换账号
2. 每日签到（福利宝箱）
3. 执行供给（福利 → 特别行动版；默认关闭，可在任务页启用）
4. 领取邮件
5. 自动吃 MIA 私厨
6. 次元历练代理战斗（武器、意志、金币三选一）
7. 检查人工岛建筑是否有「老头」红点
8. 旧日幻想潜入下一层并退出
9. 公会捐赠；可选领取公会奖励

任务顺序按任务页设置执行。需要记录老头名称或切号时，会进入设置页；若还有下一个账号，则通过用户中心切换并填写下一账号密码，进入游戏后再次核验账号身份。只有日常与账号收尾均成功，才自动取消当前账号勾选；失败或结果不明时保留勾选并停止整轮。

### 多号运行保护

- 首次启动使用「加载游戏」流程：强制重启成功后固定等待40秒，再每2秒一轮查找游戏公告，查找窗口20秒；单次固定等待与查找合计最多60秒，强停及启动游戏的操作耗时另计。布局、左上角标题和关闭 X 共用一张截图，确认后直接使用本帧 X 位置点击，只在点击后重新截图检查关闭结果。公告仍在时交由原公告关闭流程继续处理，不点击下层页面；未确认公告则强制重启，包含首次共尝试3次，仍失败便停止。后续切换账号不执行这一流程。
- 登录的账号页面导航、输入提交、身份核验和进入游戏等待均不设置原来的整体超时。暂时截图为空或尚未确认可操作页面时继续等待，可点击停止取消；不重复提交已输入的凭据。具体导航动作仍保留原有尝试次数，账号不匹配等明确失败仍停止，进入日常后恢复严格的结果确认规则。
- 首个账号的启动、登录及身份核验在日志中命名为「首次登陆流程」。该流程不识别菜单展开状态、设置页亮色布局或设置入口模板；识别主界面菜单后按固定坐标点击设置，再识别用户中心按钮。流程内不识别/取消线路选择。进入游戏加载的轮询在同一张截图上识别奖励找回，只匹配红色标题在 1280×720 画面中的固定裁切区域，命中后点击空白处关闭，并且不因此结束流程。主界面只匹配菜单，跳过副本、福利、确认弹窗及登录面板的负向排除；公告和账号相关识别仍保留。奖励找回只在首次登陆流程和后续切号中识别，日常导航与全局验证不再识别。失败诊断沿用相同识别范围，流程结束后恢复其余正常规则。
- 首次登陆流程先在用户中心核验当前账号，再点击登陆首页并确认首页特征消失；此后显示「进入游戏加载」，固定等待30秒，再每2秒一轮用同一张截图匹配游戏主界面菜单，并在奖励找回标题的固定区域内匹配奖励找回，查找窗口最多60秒。识别到奖励找回时先点击上方空白处关闭，仍在则点击下方空白处；重试1次后仍未关闭则失败停止。该帧即使同时识别到菜单也不结束流程。菜单单帧匹配成功且该帧没有奖励找回便结束首次登陆流程，不在成功后追加多帧确认或再次进入用户中心；60秒仍未找到菜单则失败停止。首页未切换时不开始该等待；核验后已直接返回游戏场景的路径也执行相同30秒加60秒确认。停止按钮可取消等待。后续切号不增加这30秒加60秒轮询，但进入游戏的等待仍用同一裁切区域识别并关闭奖励找回。为触发账号页面而点击首页的分支不增加此流程。
- 首次流程复用最终菜单确认之前取得的本轮用户中心身份；若输入了新凭据，提交后先核验新账号，再进入上述最终加载确认，不重复填写或点击登录。后续切号的操作和账号核验步骤沿用原逻辑，主界面仍要求三帧确认。
- 每日签到复用首次登陆流程或后续切换账号登陆成功时的最终主界面菜单，直接按菜单锚点向左4格点击礼盒，入口不再追加截图或菜单多帧确认；点击后仍识别福利页和签到页。菜单结果绑定已核验的账号、只消费一次；更换账号、执行其他任务、发生新的截图/输入操作或触控尺寸变化后不复用，改按当前页面正常导航。
- 每日签到后若紧接着启用执行供给，就保留福利页直接进行供给；未启用供给或下一任务不是供给时，签到完成后点击左上角退出。执行供给完成后同样点击左上角退出，包括没有黄色可领取奖励的分支。这两处退出点击后不再截图确认游戏主界面，由下一任务按需要识别当前位置。
- 不再识别“无法连接服务器”提示，也不自动点击该提示的确定按钮或按该提示触发重登。
- 登录和掉线重登后必须核验当前账号。关闭自动登录时，首个账号只做身份核验。完整手机号要求精确匹配；掩码只在全部保存账号中唯一时有效，掩码冲突或无法读取就停止。
- 除首次登陆外，同一步骤最多初次执行加一次重试；任务内部导航、整项任务重试和全局恢复共享次数，不会叠加多轮点击。截图轮询、连续帧确认和正常多次品尝不计为失败重试。
- 失败重试后进入一次全局验证：先截取当前画面，用同一张图判定位置并保存诊断，再选择处理已确认的阻挡弹窗、续接任务结果确认或导航到尚未执行的任务页面。全局恢复不清空次数和提交记录；无法判定位置或恢复仍失败时停止后续账号，在日志输出原因、最后页面及 `diagnostics/<任务>_<时间>_failure.png` 和同名 `.txt` 文件路径。
- 领取、品尝、捐赠确定、代理战斗、潜入等动作提交后，只续接原动作的结果确认和后续清理，不重新点击或重跑整项任务。供给 DAY 7、累计奖励及多次品尝分别保留进度，单个动作成功不等于整项任务完成；全局验证仍无法确认结果时停止全部账号。
- 邮件只提交一次一键领取。有奖励时确认奖励弹窗及返回邮件页；空邮箱点击没有提示，等待2秒且连续三帧确认仍在邮件页后按无可领取奖励继续。领取确认循环无总时限；领取处理完成后点击左上角社交退出，连续两帧识别右上角菜单确认返回游戏主界面后才结束任务，下一任务单次复用此菜单识别结果；新的截图、输入或切换账号会使复用结果失效。每日签到在启动日常时读取设备本地星期（周一=DAY 1，周日=DAY 7），本轮所有账号沿用该 DAY；确认签到页后，在同一张截图中定位七格并检查目标 DAY 黄色高亮；目标格无黄色高亮就不点击，直接结束签到，目标格有黄色高亮才点击一次，此后只识别奖励弹窗，确认出现后点击上方空白处关闭，确认弹窗消失即成功；未出现或关闭失败时停止，不重复点击 DAY。全程不检查对勾，其他 DAY 的高亮不影响目标格判断。执行供给确认页面后，在同一张截图中检查七个 DAY 和累计奖励的黄色高亮；两边都无黄色直接结束，只亮累计奖励则点击一次，确认累计奖励黄色消失并连续两帧出现灰色遮罩后完成。DAY 1～6 黄色时点击一次，只检查刚点击的 DAY，确认黄色消失并连续两帧出现灰色遮罩后完成；DAY 7 同样先确认目标 DAY 灰色遮罩，再只识别右侧累计奖励，黄色出现后点击一次并确认累计奖励灰色遮罩。DAY 与累计奖励同时黄色时先点击 DAY 并确认其灰色遮罩，再只识别并领取累计奖励。供给不检查对勾或七个 DAY 全部已领取状态，点击后的确认只检查当前目标区域，确认超时则停止，不重复提交领取。公会周福利用“下周可领取”确认本周已领取。
- 切号阶段禁止调用上一个账号的掉线恢复。新账号身份确认后才进入下一轮日常；停止期间禁用再次启动，新设备动作在发送前检查取消状态。
- 每轮在应用外部文件目录 `run_records/run_<ID>.jsonl` 追加账号、任务、提交、结果确认和诊断图片路径。每条立即刷新，写入失败会停止运行。进度记录使用内部账号 ID，详情遮蔽本轮账号和密码；记录用于排查，不自动从未确认动作恢复。

这一批已加入执行层保护和离线检查；云手机的识别准确率、权限和完整多号流程仍需实机验证。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Android 11+（API 30）可用无障碍截图；Android 9–10 截图需要 Shizuku |
| 权限 | Android 11+ 开启本应用无障碍；[Shizuku](https://shizuku.rikka.app/) 可选，用于强停游戏和截图兜底 |
| 游戏 | 国服包名默认 `com.pwrd.hotta.laohu`，B 服可选 `com.pwrd.hotta.mhtg` |
| 分辨率 | 游戏横屏，点击按实际屏幕像素换算；目标云手机为 1280×720、DPI 320；有模板时优先模板匹配 |

如已安装 Shizuku，可同时授权作为强停游戏和截图的兜底；Android 11+ 的无障碍截图正常时无需 Shizuku。

主界面确认只匹配右上角菜单图标：搜索范围为截图右侧15%、顶部13%，使用528像素参考高度等比例缩放，阈值0.78；日常导航要求连续两帧菜单位置稳定，后续切号登录为三帧，首次登陆最终菜单轮询单帧匹配成功即完成。短时内复用确认结果以降低截图开销。小地图、闪避和血条不参与匹配。日常任务和后续切号会排除福利页、登录面板、确认弹窗及副本状态；首次登陆流程跳过这些排除检查。诊断记录菜单得分并保存搜索区域截图。交叉形入口和礼盒仍以菜单中心向左两个、四个固定间距定位，720高度下每个间距57像素。

### 云手机（1280×720、DPI 320）

云手机为 Android 11 或更新版本时，开启本应用的无障碍服务即可进行截图和点击；DPI 320 影响系统界面大小，不参与游戏截图和点击的像素坐标换算。游戏进入横屏后，确认系统实际分辨率为 1280×720，并先用一个账号验证完整流程，再启用多账号。

提供的流程录像来自 MuMu。云手机虽然设为相同分辨率，游戏 UI 缩放、字体或画质仍可能不同；若某个步骤持续提示“未识别”，请在云手机上重新截取该按钮模板并覆盖到应用外部 `templates` 目录。截图失败会明确报错，不会当作“已领取”跳过。

## 使用

1. Android Studio 打开本目录，JDK 17，同步后运行 `app`。
2. 安装 APK 后：开启无障碍「MAA Hotta 手势服务」，并给 Shizuku 授权。
3. 在「账号」页添加通行证，勾选要跑的号。
4. 在「任务」页选择日常项目。
5. 把按钮小图放进工程目录 `app/src/main/assets/templates/`（文件名见该目录 README），然后重新 Generate APKs。关键模板缺失时任务会报错；少量已确认页面的兜底点击仍使用相对坐标。

6. 切到《幻塔》横屏，回本应用点「开始日常」。

## 任务路径（游戏内）

- 签到：启动日常读取设备本地星期 → 右上角宝箱 → 福利 → 签到 → 目标 DAY 有黄色才点击一次，确认奖励弹窗出现并关闭；目标无黄色直接完成。下一任务为供给时保留福利页，否则点击左上角退出，退出后不复查主界面
- 执行供给：右上角宝箱 → 特别行动版 → 执行供给 → 同帧检查七个 DAY 和累计奖励黄色高亮；DAY 点击一次并确认目标灰色遮罩，DAY 7 或同帧累计也亮时再只识别累计奖励黄色，点击后确认累计奖励灰色遮罩；仅累计奖励亮则直接点击并确认灰色遮罩，都不亮则直接结束。完成后点击左上角退出，不复查主界面
- 邮件：主界面右上角菜单 → 社交 → 左侧邮件 → 一键领取 → 点击奖励白框外关闭 → 返回游戏主界面
- 私厨：首次通过游戏主界面交叉形入口进入必做页 → 左侧推荐 → 检查 MIA 私厨完成标记 → 未完成则点击 MIA 私厨卡片进入 → 首次点击品尝及之前不检查弹窗；首次品尝后开始，退出、推荐、卡片和后续品尝每次点击前先识别并关闭奖励弹窗，清理后重新定位目标 → 退出到必做页推荐并检查完成标记；未完成则重复进入品尝、退出，不限制品尝点击次数，完成后停留在必做页
- 历练：确认左上角必做 → 先查找次元历练入口，未找到则再次确认必做并固定坐标点击推荐后重新查找（不要求识别推荐文字或模板） → 所选历练类型 → 参与 → 代理战斗；关闭奖励并确认返回必做页后才算完成
- 老头：沿用必做页 → 左侧休闲 → 验证休闲页中央内容 → 识别人工岛建筑卡片及其右上角红点
- 旧日幻想：沿用必做页 → 左侧挑战 → 识别中央旧日幻想卡片 → 潜入按钮消失且识别跃迁启动提示（仅判定、不点击）→ 等待3秒 → 同帧互斥识别跳过/退出，唯一命中才点击 → 跳过后继续等待退出 → 确定 → 验证返回游戏主界面
- 公会捐赠：主界面右上角菜单 → 公会 → 日常 → 立即捐献 → 验证确认文字 → 确定 → 验证可捐献次数0/1
- 公会奖励（可选）：捐赠后沿用公会页面 → 信息 → 只点击当前带红点的奖励 → 验证所有奖励红点消失 → 返回游戏主界面
- 多号切换：主界面右上角菜单 → 设置 → 读取角色名称 → 用户中心 → 切换账号 → 添加新账号 → 其他登录方式 → 输入下一账号和密码

## 人工岛老头记录

识别到人工岛建筑红点后，会在该账号进入设置页时读取角色名称，并追加到应用外部文件目录下的 `records/人工岛老头.txt`。同一份文本只追加名称且自动去重，不会因多号流程中断而覆盖已记录内容。文本创建满 24 小时后由系统定时删除，应用下次启动或写入时也会清理过期文件。

`IslandMerchantRecordApi` 是后续对接 QQ API 的预留接口；当前默认实现不发送网络请求。

## 和 MAA-Meow 的关系

Meow 把 **MAA Core**（明日方舟识别库）嵌进 Android，并用 scrcpy 系反射注入触控、虚拟屏后台。本仓库只保留同一类 **设备控制 + 任务链** 思路，游戏逻辑全部换成《幻塔》。第三方声明见 `docs/THIRD_PARTY_NOTICES.md`。许可证为 AGPL-3.0。

## 构建

离线策略检查见 `tests/execution/README.md`。设置 `MAH_TEST_OUTPUT_DIR` 后，执行、供给、HUD 和导航检查可将产物放到其他磁盘，避免在 C 盘累积。

```text
Android Studio → Open C:\Users\13367\MAA-Hotta → Sync → Run app
```

不需要 `setup_maa_core.py`。
