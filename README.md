# MAA Hotta

在 Android 上自动跑《幻塔》日常。运行方式对齐 [MAA-Meow](https://github.com/Aliothmoon/MAA-Meow)：无障碍/Shizuku 截图与点击、悬浮控制、任务链。不包含明日方舟或 MAA Core。

## 能做什么

按账号循环执行：

1. 登录 / 切换账号
2. 每日签到（福利宝箱）
3. 执行供给（福利 → 特别行动版；默认关闭，可在任务页启用）
4. 领取邮件
5. 自动吃 MIA 私厨
6. 次元历练代理战斗（武器、意志、金币三选一）
7. 检查人工岛建筑是否有「老头」红点
8. 旧日幻想潜入下一层并退出
9. 公会捐赠；可选领取公会奖励

任务顺序按任务页设置执行。需要记录老头名称或切号时，会进入设置页；若还有下一个账号，则通过用户中心切换并填写下一账号密码，进入游戏后再次核验账号身份。只有日常与账号收尾均成功，才自动取消当前账号勾选；失败或结果不明时保留勾选并停止整轮。

### 多号运行保护

- 填写账号密码、离开登录页之后的游戏加载、账号核验各自使用 120 秒等待窗口。点击登录后只花最多 10 秒按蓝色登录按钮确认是否离开密码页，按钮连续消失才重新计时 120 秒，不与填密码共用，也不在登录页上空等整段加载时间。窗口内暂时截图为空或尚未确认可操作页面时继续等待，不因此重复提交输入。到期仍无法确认才停止，进入日常后恢复严格的结果确认规则。
- 同一轮已在用户中心核验当前账号、随后进入主界面并通过三帧确认时，复用本轮身份；切号或提交登录凭据后重新核验。已完成的三帧证据不会因超时边界再要求第四帧。
- 不再识别“无法连接服务器”提示，也不自动点击该提示的确定按钮或按该提示触发重登。
- 登录和掉线重登后必须核验当前账号。关闭自动登录时，首个账号只做身份核验。完整手机号要求精确匹配；掩码只在全部保存账号中唯一时有效，掩码冲突或无法读取就停止。
- 领取、品尝、捐赠确定、代理战斗、潜入等动作提交后，结果不明就停止全部账号，不重新点击或重跑整项任务。已确认领取后，页面清理异常同样不会重放领取。尚未提交动作的导航失败保留一次有界重试。
- 邮件只提交一次一键领取。有奖励时确认奖励弹窗及返回邮件页；空邮箱点击没有提示，等待10秒且连续三帧确认仍在邮件页后按无可领取奖励继续。出现过奖励弹窗但结果未确认、或页面状态不明时停止。签到和供给的历史日奖励不能单独证明今日完成；公会周福利用“下周可领取”确认本周已领取。
- 切号阶段禁止调用上一个账号的掉线恢复。新账号身份确认后才进入下一轮日常；停止期间禁用再次启动，新设备动作在发送前检查取消状态。
- 每轮在应用外部文件目录 `run_records/run_<ID>.jsonl` 追加账号、任务、提交、结果确认和诊断图片路径。每条立即刷新，写入失败会停止运行。进度记录使用内部账号 ID，详情遮蔽本轮账号和密码；记录用于排查，不自动从未确认动作恢复。

这一批已加入执行层保护和离线检查；云手机的识别准确率、权限和完整多号流程仍需实机验证。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Android 11+（API 30）可用无障碍截图；Android 9–10 截图需要 Shizuku |
| 权限 | Android 11+ 开启本应用无障碍；[Shizuku](https://shizuku.rikka.app/) 可选，用于强停游戏和截图兜底 |
| 游戏 | 国服包名默认 `com.pwrd.hotta.laohu`，B 服可选 `com.pwrd.hotta.mhtg` |
| 分辨率 | 游戏横屏，点击按实际屏幕像素换算；目标云手机为 1280×720、DPI 320；有模板时优先模板匹配 |

如已安装 Shizuku，可同时授权作为强停游戏和截图的兜底；Android 11+ 的无障碍截图正常时无需 Shizuku。

主界面确认只匹配右上角菜单图标：搜索范围为截图右侧15%、顶部13%，使用528像素参考高度等比例缩放，阈值0.78；日常导航要求连续两帧菜单位置稳定（登录仍为三帧），短时内复用确认结果以降低截图开销。小地图、闪避和血条不参与匹配。福利页、登录面板、确认弹窗及副本状态通过流程排除。诊断记录菜单得分并保存搜索区域截图。交叉形入口和礼盒仍以菜单中心向左两个、四个固定间距定位，720高度下每个间距57像素。

### 云手机（1280×720、DPI 320）

云手机为 Android 11 或更新版本时，开启本应用的无障碍服务即可进行截图和点击；DPI 320 影响系统界面大小，不参与游戏截图和点击的像素坐标换算。游戏进入横屏后，确认系统实际分辨率为 1280×720，并先用一个账号验证完整流程，再启用多账号。

提供的流程录像来自 MuMu。云手机虽然设为相同分辨率，游戏 UI 缩放、字体或画质仍可能不同；若某个步骤持续提示“未识别”，请在云手机上重新截取该按钮模板并覆盖到应用外部 `templates` 目录。截图失败会明确报错，不会当作“已领取”跳过。

## 使用

1. Android Studio 打开本目录，JDK 17，同步后运行 `app`。
2. 安装 APK 后：开启无障碍「MAA Hotta 手势服务」，并给 Shizuku 授权。
3. 在「账号」页添加通行证，勾选要跑的号。
4. 在「任务」页选择日常项目。
5. 把按钮小图放进工程目录 `app/src/main/assets/templates/`（文件名见该目录 README），然后重新 Generate APKs。关键模板缺失时任务会报错；少量已确认页面的兜底点击仍使用相对坐标。

6. 切到《幻塔》横屏，回本应用点「开始日常」。

## 任务路径（游戏内）

- 签到：右上角宝箱 → 福利 → 签到 → 领取
- 执行供给：右上角宝箱 → 特别行动版 → 执行供给 → 黄色高亮的 DAY 奖励；累计奖励解锁后领取
- 邮件：主界面右上角菜单 → 社交 → 左侧邮件 → 一键领取 → 点击奖励白框外关闭 → 返回游戏主界面
- 私厨：首次通过游戏主界面交叉形入口进入必做页 → 左侧推荐 → 识别中央 MIA 私厨卡片 → 品尝；完成后停留在必做页
- 历练：沿用必做页 → 左侧推荐 → 识别中央次元历练卡片 → 所选历练类型 → 参与 → 代理战斗；完成后停留在必做页
- 老头：沿用必做页 → 左侧休闲 → 验证休闲页中央内容 → 识别人工岛建筑卡片及其右上角红点
- 旧日幻想：沿用必做页 → 左侧挑战 → 识别中央旧日幻想卡片 → 潜入按钮消失且识别跃迁启动提示（仅判定、不点击）→ 等待3秒 → 同帧互斥识别跳过/退出，唯一命中才点击 → 跳过后继续等待退出 → 确定 → 验证返回游戏主界面
- 公会捐赠：主界面右上角菜单 → 公会 → 日常 → 立即捐献 → 验证确认文字 → 确定 → 验证可捐献次数0/1
- 公会奖励（可选）：捐赠后沿用公会页面 → 信息 → 只点击当前带红点的奖励 → 验证所有奖励红点消失 → 返回游戏主界面
- 多号切换：主界面右上角菜单 → 设置 → 读取角色名称 → 用户中心 → 切换账号 → 添加新账号 → 其他登录方式 → 输入下一账号和密码

## 人工岛老头记录

识别到人工岛建筑红点后，会在该账号进入设置页时读取角色名称，并追加到应用外部文件目录下的 `records/人工岛老头.txt`。同一份文本只追加名称且自动去重，不会因多号流程中断而覆盖已记录内容。文本创建满 24 小时后由系统定时删除，应用下次启动或写入时也会清理过期文件。

`IslandMerchantRecordApi` 是后续对接 QQ API 的预留接口；当前默认实现不发送网络请求。

## 和 MAA-Meow 的关系

Meow 把 **MAA Core**（明日方舟识别库）嵌进 Android，并用 scrcpy 系反射注入触控、虚拟屏后台。本仓库只保留同一类 **设备控制 + 任务链** 思路，游戏逻辑全部换成《幻塔》。第三方声明见 `docs/THIRD_PARTY_NOTICES.md`。许可证为 AGPL-3.0。

## 构建

离线策略检查见 `tests/execution/README.md`。设置 `MAH_TEST_OUTPUT_DIR` 后，执行、供给、HUD 和导航检查可将产物放到其他磁盘，避免在 C 盘累积。

```text
Android Studio → Open C:\Users\13367\MAA-Hotta → Sync → Run app
```

不需要 `setup_maa_core.py`。
